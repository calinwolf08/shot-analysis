# Deviations log

Deviations from `docs/implementation-plan-training-app.md`, with reasons.

| Step | Deviation                                                                                                                                                 | Reason                                                                                                                                                                                                                                                                    |
| ---- | --------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 1    | Dropped `@testing-library/jest-dom` (plan implied standard testing-library stack). Component tests use plain vitest assertions + testing-library queries. | The root library workspace pins vitest 2 while the app uses vitest 3; npm hoisting makes jest-dom's `declare module "vitest"` augmentation land on the wrong vitest copy, breaking `svelte-check`. Queries already throw on missing elements, so the matchers add little. |
| 1    | `svelteTesting()` vite plugin is cast to `PluginOption` in `vite.config.ts`.                                                                              | Two vite majors exist in the monorepo (library tooling vs app); plugin types are runtime-compatible but not identical at the type level.                                                                                                                                  |
| 2    | `cap sync` on Linux skips `pod install` / xcodebuild for iOS (warning, exit 0).                                                                           | CocoaPods/Xcode require macOS. iOS dependency install is a documented manual step in `docs/device-testing.md`.                                                                                                                                                            |
| —    | Root library test `src/testing/reporting.test.ts` ("read-only directory") fails in this container.                                                        | Pre-existing: the test relies on chmod-based write denial, which does not apply when running as root. Unrelated to the app; passes as non-root.                                                                                                                           |

| 5 | Web persistence uses sql.js + manual IndexedDB image export instead of `jeep-sqlite`. | Fewer moving parts: same sql.js engine, a ~60-line BytesStore, deterministic in e2e. The Capacitor plugin web layer (jeep-sqlite) would add a custom element + duplicate wasm delivery for no additional capability here. |

| 7 | Added `ShotDetector`, `MetricOrchestrator`, calculator factories, `detectOrientation`, pose-format types and `poseDataSchema` to the library's root barrel (`src/index.ts`, additive only). | The plan assumed these were already public exports; they were exported from module indexes but not the package root, and the package's `main` points at `dist/index.js`. No behavior change; library tests unaffected. |
| 7 | Replay pipeline rebases frame indexes/timestamps onto the pose-filtered sequence before metric extraction. | `ShotDetector.processFrames` frame ranges index the filtered array; keeping original camera frame indexes starves timing calculators wherever a frame had no detected pose (12 vs 27 confident metrics on the 3-shot fixture). All frame refs in stored results are filtered-sequence indexes, consistently. |
| 7 | Fixture set is 1-shot/3-shot/7-shot: `20201212_134104`, `20190103_180930`, `20190804_140654`. | The plan's example id for the 7-shot video (`20181219_173607`) is actually a 4-shot video per its labels; `20190804_140654` is the 7-shot one. |

| 8 | MediaPipe WASM runtime is staged from the locked npm package by `scripts/fetch-mediapipe-assets.ts` (gitignored, ~22 MB); only the pose model (~9 MB) is committed. | The plan preferred committing everything; the WASM comes byte-identical from the locked dependency, so committing it would only bloat the repo. Offline installs still work (model committed, wasm from node*modules). |
| 8 | Live window analysis (`analyzeWindow`) runs on the main thread, not in the worker. | It is pure JS over already-extracted landmarks with a bounded (~12 s) window; a worker round-trip would add latency for no responsiveness gain. Pose \_detection* stays in the worker. |

| 9 | Benchmarked metric set is the library pro-form profile's 26 metrics; the analyzer's additional `releasePoint` metric has no benchmark target and is excluded from scoring. | The design doc says "26 metrics" but its name list contains 27; the library's canonical profiles target 26 (no `releasePoint`). Stored ShotAnalysis JSON still contains releasePoint values for future use. |

| 16 | Placeholder drill video is WebM/VP8 (`static/drills/placeholder.webm`), generated by recording a canvas animation in headless Chromium (MediaRecorder) via `scripts/make-placeholder-drill-video.ts`; the "coming soon" text lives in the SVG poster. | The plan suggested an ffmpeg-generated MP4 with drawtext. The only ffmpeg in this container is Playwright's screencast build, which has no rawvideo demuxer, no lavfi/drawtext, and no H.264 — only mjpeg/vp8 in, vp8/webm out. Chromium's MediaRecorder produces a real VP8 WebM every browser target plays. |
